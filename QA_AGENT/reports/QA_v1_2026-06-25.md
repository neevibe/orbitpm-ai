## Check 2 — ESLint (`npm run lint`)

**Status: ❌ FAIL — Lint pipeline is broken**

### Error Output

```
ESLint: 9.39.4

A configuration object specifies rule "react-hooks/rules-of-hooks", but could not
find plugin "react-hooks".
```

### Root Cause

The `eslint.config.mjs` spreads `eslint-config-next/core-web-vitals` and then declares `react-hooks/rules-of-hooks` and `react-hooks/exhaustive-deps` in a **separate** rules object — but the `react-hooks` plugin is not imported/registered in that same config object. In ESLint 9's flat config, plugins must be present in the same config object as their rules.

### Affected File
`eslint.config.mjs` lines 14–15:

```js
// BROKEN — plugin not imported/registered in this config object
"react-hooks/rules-of-hooks": "warn",
"react-hooks/exhaustive-deps": "warn",
```

### Recommendation (Priority: HIGH)

**Option A (Simplest):** Remove lines 14–15 from the custom rules block. These rules are already inherited from `eslint-config-next/core-web-vitals` via the spread at line 6. The duplicate declaration in a separate config object without the plugin registered is what breaks the linter.

**Option B:** Import and register `eslint-plugin-react-hooks` explicitly in the same config object that uses its rules.

Option A is recommended — it requires zero new dependencies.

### Additional Config Debt

The config also declares non-existent rule names (lines 16–19) which should be removed:
- `react-hooks/preserve-manual-memoization` — not a real rule
- `react-hooks/set-state-in-effect` — not a real rule  
- `react-hooks/purity` — not a real rule

## Additional Findings

### Portfolio Page — Budget Double-Count Bug

**Severity: MEDIUM**

In `portfolio/page.tsx` lines 24 and 39, the budget rollup guards against mirror rows using:
```tsx
if ((p as any).isDuplicateDependency) return;  // WRONG flag
```

But the canonical property throughout the codebase is `isDependencyMirror` (defined in `mock-data.ts:99`, used in `data-context.tsx:250`, `projects/page.tsx:174`, etc.).

Since no project ever has `isDuplicateDependency = true`, this guard **never fires**. Mirror rows are included in the budget calculation, potentially **inflating "Total Investment"** and department budget chart values.

**Fix required:**
```tsx
if (p.isDependencyMirror) return;  // correct flag — no `as any` cast needed
```
